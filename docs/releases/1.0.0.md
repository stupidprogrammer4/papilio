# Papilio 1.0.0

Release preparation; no package publication or release tag is implied by this
page. Python 3.13+ is required. The distribution, imports and CLI are named
`papilio`; older Fastamu tags belong to the pre-split project.

## What is included

- Application-owned FastAPI entrypoints, module discovery and explicit Dishka
  providers. Optional infrastructure and tools are installed through extras.
- Backend-specific SQL repositories and write contracts, shared read helpers,
  explicit transaction ownership and native bulk operations.
- Elasticsearch `ESStore`, async file and CSV tools, and typed Excel processing
  in spawned workers.
- Plain frozen `PatchResult[T, P]` and `DeleteResult[T]` containers. Applications
  choose their payloads, applied-patch representation and HTTP serialization.
- Validated `QueryPair` inputs, JSON-compatible application error responses,
  whole-string slug validation and exact decimal parsing of currency strings.
- `papilio run` with Uvicorn, Gunicorn native ASGI or FastAPI CLI, development
  and production modes, configurable host/port/workers/reload, and Rich CLI help.
- GitHub CI with Python 3.13/3.14, live PostgreSQL/MySQL/MariaDB/SQLite tests,
  distribution checks and Telegram notifications.

## Upgrade from earlier checkouts

This is a breaking migration from Fastamu and intermediate Papilio APIs.
Generated application code belongs to your project and is not rewritten when
Papilio is upgraded.

| Previous usage | Required change |
| --- | --- |
| `fastamu` or `papilio_api` imports and CLI | Use `papilio`; review application imports and dependencies. |
| Bundled modules, task execution or messaging | Supply application modules explicitly. Task execution and messaging belong to the separate Papilio Tasks project. CQRS does not synchronize SQL and Elasticsearch. |
| `papilio.infra.db.models` and `.fields` | Use `.schema.entity` and `.schema.fields`. PostgreSQL classes use the `PG` prefix; select the matching backend provider, UoW and repository. |
| A shared write return contract for every database | Follow the [backend return-value table](../guide/repositories.md#understand-backend-return-values). MySQL `bulk_create` becomes count-returning `bulk_insert` with explicit insertion columns. Returning deletes return models; MySQL deletes return counts. |
| `ESRepository`, `bulk_insert`, `patch_by_id` | Use `ESStore`, `bulk_index` and `patch`. `bulk_create` is create-only. See the [ES migration](../guide/cqrs.md#migration-from-esrepository). |
| Automatic `BaseQuery` aliases, `__mapped__`, `pairs_read`, `query.folded(...)` | Declare `Field(alias=...)`, use `list[QueryPair]` and call `pairs_folded(query.picks)`. Raw pair strings validate to integer tuples. See the [query migration](../guide/api.md#query-models). |
| Implicit providers, security dependencies and rate limiting | Register selected providers and HTTP adapters explicitly. Follow the [tool migration list](../guide/tools.md#migration) for provider imports, checks, IDs, bearer authentication, passwords and CSRF. |
| Locally defined Excel row classes or unpickleable row values | Define row classes at module scope and use pickleable values so spawned workers can import and convert them. |

`SlugType` now rejects trailing invalid characters and values outside 2–55
characters. Currency strings are parsed with `Decimal` before rounding; exact
halfway amounts round to the even integer. A float that already lost precision
cannot recover it during conversion.

Existing configuration files without `run` remain valid. `papilio run` selects
an ASGI object from `--app`, `run.entrypoint` or `[tool.fastapi].entrypoint`.
Runner options follow CLI > YAML > mode defaults. Explicit YAML host values
survive mode changes. `--config` exports the selected path through
`PAPILIO_CONFIG` to workers; application settings still load through the normal
settings loader. See [runner operations](../guide/operations.md).

## Supported checks and limits

CI runs on Ubuntu with Python 3.13 and 3.14, PostgreSQL 17, MySQL 8.4,
MariaDB 11.4 and SQLite. It exercises all six runner/backend mode combinations,
including development reload, production workers, selected configuration and
lifespan shutdown. It also checks lint, types, documentation, source/wheel
contents and installation of the base-only wheel.

Gunicorn requires Unix and `gunicorn>=26.2,<27`, using its native ASGI worker;
its extra does not require Uvicorn. Live Windows/macOS, Oracle/MSSQL and
Elasticsearch/Redis deployments are outside this CI matrix. Windows launcher
behavior and ES/Redis interactions have isolated tests, not live platform or
service validation. No general throughput or full protocol certification is
claimed. See [CI coverage](../guide/testing.md#framework-ci).

## Before publishing

Confirm the final version commit passes CI and its Telegram notification, review
migration changes for your applications, then publish the reviewed wheel and
source distribution through the project's authorized release process. CI does
not publish packages or create release tags.
