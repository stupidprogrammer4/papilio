# Papilio 1.5.0

Run an independent MCP application with
`papilio.mcp.application.create_app`. It discovers providers and MCP tools from
the selected modules, owns a separate Dishka root and uses the SDK's native
HTTP application. It does not discover or mount HTTP API routers.

An optional `server_factory(container)` supplies a configured native MCP server,
including a Function Tools server using the same application services. Papilio
composes SDK and application lifespans, then closes the root dependencies.
Request scopes retain the existing executor's cleanup and transaction behavior.

The Function Tools MCP builder accepts the SDK's `auth`, `token_verifier` and
`auth_server_provider` settings. Authentication, permitted tool discovery,
business authorization and write approval remain application responsibilities.
The factory does not provide an employee login or an identity provider.

The existing API factory and mounted MCP integration are unchanged. No database
or search-index migration is required. See the [MCP guide](../guide/mcp.md) for
standalone composition and the [Function Tools guide](../guide/function-tools.md)
for the optional adapter.
