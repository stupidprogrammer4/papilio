# Papilio 1.1.0

Python 3.13+ is required. This additive release introduces opt-in SQL conflict
translation; existing undecorated operations retain their native exceptions.

## Optional database conflict translation

```python
from papilio.infra.db.tools.conflicts import handle_conflicts


@handle_conflicts
async def create_product(repo, data):
    return await repo.create(data)
```

Call the decorated function with an open, active UoW. Its connection selects
the dialect automatically. Recognized unique/primary-key violations become
`ConflictException` with HTTP 409; other errors propagate unchanged. The
decorator is independent of transaction management and performs no queries,
commits, rollbacks or retries.

`entity`, `message` and `message_code` are optional. Generated messages use an
explicit entity string/model class, or `self.entity` on a bound `Checks` method,
then generic record wording. The default code is `conflict`. Reliable fields
and values are included in the existing `unique_dict`, otherwise `{}`; native
errors remain chained as the cause.

For commit-time errors, put `@handle_conflicts` outside `@transactional`.
Errors occurring after the decorated call returns are outside its scope.
Each call belongs to the UoW/backend active at entry. See the
[full usage and boundary rules](../guide/transactions.md#optional-conflict-translation).

## Other changes since 1.0.0 preparation

- PostgreSQL unique-error decoding preserves single-column values containing
  commas and whitespace, rejects ambiguous mappings, and recognizes psycopg2
  error codes alongside asyncpg diagnostics.
- Bundled Swagger UI supports OpenAPI 3.1, preserving offline documentation.
- Redis extras accept redis-py 7 or 8 for compatibility with Papilio Tasks and
  taskiq-redis 1.2.3.

## Compatibility and verification scope

No changes to the `ConflictException` response schema, repository APIs, UoW or
transaction behavior are required. Conflict translation is off unless applied.
CHECK, foreign-key and NOT NULL errors retain native exception behavior.

CI exercises Python 3.13/3.14 and live PostgreSQL, MySQL, MariaDB and SQLite.
Oracle and SQL Server conflict classification has driver-shaped tests; live
servers for those two backends are outside the CI matrix. These tests do not
establish production throughput or every driver/server combination.

For earlier Fastamu checkouts, follow the
[1.0.0 migration guide](1.0.0.md#upgrade-from-earlier-checkouts).
