# Papilio 1.6.0

`papilio.infra.excel.stream.ExcelStreamWriter` adds an independent streaming
Excel export API. The existing `ExcelWriter` keeps its template editing API and
behavior.

Open an export with `ExcelStreamWriter(max_batch_rows=250).open(output,
template=template)`. Inside the asynchronous context, send bounded sequences
of `ExcelRow` models through `await document.write_rows(rows, sheet="Items")`.
`write_row` supports a single row. Each sheet advances independently; an
explicit `start_row` can move its cursor forward. It cannot revisit rows that
have already been written.

A dedicated spawned worker owns row conversion and the write-only workbook.
Each batch waits for its acknowledgement before another is sent. The workbook
is saved once and replaces the destination atomically on successful context
exit. An error or cancellation aborts the worker, removes temporary output and
preserves an existing destination. Row classes must be importable at module
scope, and their data must be pickleable.

Generated worksheet cells are streamed rather than retained. The template is
loaded normally once in the worker; memory still depends on the template,
batch size and workbook styles. This API does not make arbitrary large
templates constant in memory.

In a local 108-column, 10,000-row export, worker peak memory was 55.9 MiB with
streaming and 363.0 MiB with the existing writer. Streaming took 32.902 seconds;
one existing-writer call took 17.714 seconds and did not repeat detail styles
beyond the template rows. Streaming therefore trades some throughput for lower
memory and repeated formatting in this workload. These measurements are not a
performance guarantee; `benchmarks/excel_stream.py` provides the repository
benchmark.

Streaming preserves supported template values, sheet order and layout. Detail
styles repeat from `repeat_style_row=2` by default. Sheets can receive their
data in a different order from their position in the template, including a
summary written after all detail batches. A mapping selects a different style
row for each sheet; `None` disables repeated styles. Unsupported template
features are rejected. Use the existing writer when workbook editing requires
those features; streaming cannot provide arbitrary cell updates.

See the [streaming Excel guide](../guide/excel-streams.md) for the supported
template boundary and complete usage. Install the existing `excel` extra;
this release requires no database migration or application configuration
change.
