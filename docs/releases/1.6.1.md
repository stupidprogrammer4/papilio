# Papilio 1.6.1

Streaming Excel exports reuse a bounded set of public openpyxl cells for
generated scalar rows. Native worksheet append consumes each row before the
next reuse. Temporal values keep independent styles, preserving number formats
when value types change between rows and batches. The API, template overlay,
workbook publication and cancellation behavior remain unchanged.

The repository benchmark now checks stored values and semantic formatting
hashes, reports the XML engine and imported streaming module, and provides an
equally formatted normal-workbook reference. This corrects the comparison in
the 1.6.0 notes: the original writer did not repeat detail styles, so its timing
was not an equivalent formatted baseline. That earlier benchmark environment
also lacked lxml, which was already available in the consuming backend.

In the backend environment with lxml enabled, a local 108-column, 10,000-row
export took 31.437 seconds with 1.6.0. Candidate runs took 26.713–31.553 seconds,
with worker peak memory around 62 MiB. Stored-value and semantic formatting
hashes matched. Shared-machine timing variation overlaps the baseline, so
these measurements do not establish a consistent wall-time improvement or a
performance guarantee.

One paired 2,000-row run recorded worker CPU time of 8.453 seconds with 1.6.0
and 7.767 seconds with this correction, with matching data and formatting.
That single observation does not establish a general speedup.

See the [streaming Excel guide](../guide/excel-streams.md) for the unchanged
supported template boundary. No dependency, configuration or database
migration is required; the existing template-editing `ExcelWriter` is unchanged.
