# Papilio 1.3.0

Python 3.13+ is required. This additive release introduces Function Tools for
calling typed application capabilities inside the host process.

SQL extras require SQLAlchemy `>=2.0.49,<2.1.0` and SQLModel `>=0.0.38,<0.0.48`,
matching Papilio's statement and result typing contracts. SQLAlchemy 2.1 and
SQLModel 0.0.48 introduce a different native typing contract and are outside
this release's supported range.

## Function Tools

Declare async functions using `FunctionTools` from
`papilio.function_tools.registry`. Each tool has a stable key, model name,
human title, description, explicit `ToolEffect` and application authorization
hook. Write tools also require an application approval hook.

`FunctionToolExecutor` from `papilio.function_tools.execution` validates native
Pydantic argument and result contracts, hides injected dependencies and creates
an independent Dishka request scope for every invocation. Application services
retain their transaction boundaries. The executor does not own the host
container, actor policy or business replay receipts.

`Bootstrapper.boot_function_tools()` discovers explicit collections under each
selected module's `function_tools` package. Generate declarations with
`papilio module assistant --plain --function-tools`; the flag also supports
CRUD, CQRS and context modules and may be combined with `--mcp`.
Generated authorization and approval hooks fail closed until implemented.

## Optional adapters

Install `papilio[function-tools-pydantic-ai]` to use the native Pydantic AI
function toolset and deferred approval primitives. Install `papilio[mcp]` for
the native MCP adapter. Both invoke the same guarded executor; base imports
require neither SDK. Existing MCP application wiring remains compatible.

The MCP adapter accepts named parameters; positional-only and variadic
functions are rejected during composition because their SDK contracts differ.
Applications must authenticate callers and filter discovery. Framework approval
hooks enforce the application's policy even after model approval.

See the [Function Tools guide](../guide/function-tools.md) for complete
registration, discovery, lifecycle and adapter examples.

## Verification boundaries

Scoped checks exercise native typed contracts, request isolation, cancellation,
SQLite transactions and fresh reads, SDK MCP calls, controlled model approval
and generated PostgreSQL modules. Controlled authorization/model contexts do
not prove application-specific permission parity or live model inference.
Business idempotency and recovery remain the application's responsibility.
